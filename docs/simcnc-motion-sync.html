Why Motion-Synchronized Torch Control Is Required in SimCNC

By default, CSLab SimCNC fires and extinguishes the plasma torch through asynchronous macro calls (d.setSpindleState() / d.setThcState()) coupled with velocity-zero stalls (d.waitForZeroVelocity()). While adequate for basic stationary pierces and stops, asynchronous relay switching forces the motion planner to decelerate to a complete halt before turning the torch off—making Zero-Overburn Early Torch-Out (killing the arc mid-motion on a lead-out or hole overburn sweep) and 3D Ramp Lead-Ins (Flying Pierce) physically impossible without burning a divot into the tube wall.

To achieve sub-millisecond, lookahead-synchronized plasma control in SimCNC—required for RotaryCAM's 3D Ramp Lead-In and Zero-Overburn Early Extinguish features—this guide implements three architectural upgrades across config.xml, ___CONF.py, m3.py, m5.py, and the RotaryCAM Post-Processor:

  • 1. Hardware Trajectory Sync Channels (ExtTrajSyncOut1 / P1 & ExtTrajSyncOut0 / P0): Reassign the physical Torch Fire Relay (Output 0) and Hardware THC Lock (Output 4) to SimCNC's hardware trajectory sync channels (ExtTrajSyncOut1 / P1 and ExtTrajSyncOut0 / P0), switched deterministically inside the real-time trajectory planner via M62 P<n> (ON) and M63 P<n> (OFF).
  • 2. Direct CSMIO/IP-M Hardware Arc OK Polling (Digital Input 0): Poll the optically isolated Arc OK input (Digital Input 0) directly on the CSMIO/IP-M hardware module rather than waiting on SimCNC's internal software THC state machine (#4071).
  • 3. Solving SimCNC's Stationary ExtTrajSync Constraint (<1.5 ms Micro-Wiggle): When an output pin is assigned to ExtTrajSyncOut, SimCNC blocks direct mod.setDigitalIO() calls, and M62/M63 commands only toggle the physical pin when a trajectory interpolation step occurs. Stationary macros (m3.py / m5.py) execute an atomic, zero-net-displacement Z-axis micro-wiggle (±0.0005" / ±0.01 mm) immediately after M62/M63 to trip the hardware output in <1.5 ms, while mid-motion G-code (M63 P1 before a lead-out or overburn arc) extinguishes the torch on-the-fly at full cutting speed.
Torch Fire Relay (P1) ExtTrajSyncOut1 → Output 0 (M62/M63 P1)
Hardware THC Lock (P0) ExtTrajSyncOut0 → Output 4 (M62/M63 P0)
Direct Arc OK Input CSMIO/IP-M Digital Input 0 (5 ms Poll)
Part I • Real-Time Trajectory I/O Synchronization

Step 03

Create Trajectory-Sync & Hardware Arc-OK Helpers in ___CONF.py

Create shared helper functions in ___CONF.py and import them (from ___CONF import *) in both m3.py:7 and m5.py:5:

  • 1. Pin Constants (___CONF.py:4-23):
    • THC_Sync_Pin = "P0" (ExtTrajSyncOut0 → Output 4)
    • Arc_Sync_Pin = "P1" (ExtTrajSyncOut1 → Output 0)
    • Arc_OK_Pin = 0 and Arc_OK_Inverted = True (CSMIO/IP-M Digital Input 0, active-low DIOPinVal.PinReset when conducting).
  • 2. Stationary Micro-Wiggle Trigger (trigger_motion_sync(), fire_torch_hardware(), extinguish_torch_hardware()): Uses d.executeGCodeList() to submit M62 P1 (or M63 P1 + M63 P0) followed by a relative G91 Z-axis step out and back (±0.0005" at F100.0 in imperial, or ±0.01 mm at F2500.0 in metric) and G90. Submitting as a single list avoids multi-roundtrip UDP latency and immediately latches/clears the hardware relay while stationary.
  • 3. Direct Hardware Arc OK Check (check_arc_ok()): Reads mod.getDigitalIO(IOPortDir.InputPort, Arc_OK_Pin) directly on ModuleType.IP, 0 instead of reading SimCNC parameter #4071.
___CONF.py — Trajectory-Sync & Direct Hardware Arc-OK Helpers PYTHON 
# ___CONF.py — Shared Hardware Trajectory Sync & Direct Arc-OK Helpers
THC_Sync_Pin = "P0"      # ExtTrajSyncOut0 -> CSMIO/IP-M Digital Output 4 (Hardware THC Lock)
Arc_Sync_Pin = "P1"      # ExtTrajSyncOut1 -> CSMIO/IP-M Digital Output 0 (Plasma Torch Fire Relay)

Arc_OK_Pin = 0           # CSMIO/IP-M Digital Input 0 (Optically Isolated Arc OK)
Arc_OK_Inverted = True   # Active-low: DIOPinVal.PinReset when plasma arc is conducting


def _wiggle_params(d):
    """Return zero-net-displacement Z micro-wiggle step and feedrate for current machine units."""
    try:
        is_inch = ("inch" in gui.edPlasmaUnits.getText().lower())
    except Exception:
        is_inch = False
    if is_inch:
        return ("0.0005", "100.0")
    return ("0.01", "2500.0")


def trigger_motion_sync(d):
    """Execute a zero-net-displacement Z micro-wiggle to flush pending M62/M63 pins while stationary."""
    step, feed = _wiggle_params(d)
    d.executeGCodeList([
        "G91",
        f"G1 Z{step} F{feed}",
        f"G1 Z-{step} F{feed}",
        "G90"
    ])


def fire_torch_hardware(d):
    """Latch ExtTrajSyncOut1 (Output 0) ON while stationary in <1.5ms via atomic GCode list."""
    step, feed = _wiggle_params(d)
    d.executeGCodeList([
        f"M62 {Arc_Sync_Pin}",
        "G91",
        f"G1 Z{step} F{feed}",
        f"G1 Z-{step} F{feed}",
        "G90"
    ])


def extinguish_torch_hardware(d):
    """Clear Torch Relay (P1) and lock THC (P0) while stationary via atomic GCode list."""
    step, feed = _wiggle_params(d)
    d.executeGCodeList([
        f"M63 {Arc_Sync_Pin}",
        f"M63 {THC_Sync_Pin}",
        "G91",
        f"G1 Z{step} F{feed}",
        f"G1 Z-{step} F{feed}",
        "G90"
    ])


def check_arc_ok(d):
    """Read optically isolated Arc OK input directly from CSMIO/IP-M Module 0 Digital Input 0."""
    mod = d.getModule(ModuleType.IP, 0)
    pin_state = mod.getDigitalIO(IOPortDir.InputPort, Arc_OK_Pin)
    if Arc_OK_Inverted:
        return (pin_state == DIOPinVal.PinReset)
    return (pin_state == DIOPinVal.PinSet)

  • 3.   • 4. 3D Ramp Lead-In Handoff & Removal of Post-Pierce Velocity Stall (m3.py:604-626 vs. stock m3.py:198-218): If 3D ramp lead-in is armed (#1113 == 1.0), m3.py leaves Z at Pierce_height and resets #1113 to 0.0 so the immediately following G-code lead-in move plunges Z from Pierce_height to Cut_height synchronously with XY/A motion. Step 05

Update m5.py for Dual-Path Arc Extinguish

Comparing the dual-path m5.py against SimCNC's stock m5.py:

  • 1. Check Live Hardware Arc State (m5.py:51-52): Read arc_active = check_arc_ok(d) at the very start of M5.
  • 2. Branch 1 — Arc Still Active (Stationary Stop, m5.py:54-63): If arc_active is True (e.g., open path cut, manual stop, or early extinguish disabled), call extinguish_torch_hardware(d) to execute M63 P1 + M63 P0 + Z micro-wiggle in a single atomic block, then poll check_arc_ok(d) for up to 0.5 s until the arc is confirmed out.
  • 3. Branch 2 — Arc Already Extinguished On-The-Fly (Fast No-Motion Cleanup, m5.py:64-75): If the G-code already issued M63 P1 during a lead-out or hole overburn move, the torch relay opened in hardware while moving and arc_active is already False. m5.py skips the Z micro-wiggle and eliminates the stock d.waitForZeroVelocity(1) stall (m5.py:74-83), issuing only d.executeGCode("M63 P1"), d.executeGCode("M63 P0"), and d.setSpindleState(SpindleState.OFF) before retracting immediately to the next cut.
m5.py (Lines 51–75) — Dual-Path Stationary vs. On-The-Fly Arc Extinguish PYTHON 
from ___CONF import *

# 1. Check Live Hardware Arc State (m5.py:51-52)
arc_active = check_arc_ok(d)

if arc_active:
    # Branch 1: Arc still active (stationary stop) -> atomic M63 P1 + M63 P0 + Z micro-wiggle
    extinguish_torch_hardware(d)
    t_timeout = time.time() + 0.5
    while check_arc_ok(d) and time.time() < t_timeout:
        time.sleep(0.005)
else:
    # Branch 2: Arc already extinguished on-the-fly by M63 P1 during lead-out / overburn!
    # Skip Z micro-wiggle & skip waitForZeroVelocity(1) for instant retract to Safe Z
    d.executeGCode(f"M63 {Arc_Sync_Pin}")
    d.executeGCode(f"M63 {THC_Sync_Pin}")

d.setSpindleState(SpindleState.OFF)
Step 06

Emit Synchronized M62/M63 in G-Code (RotaryCAM Post-Processor)

To take full advantage of your motion-synchronized SimCNC configuration during cutting, the RotaryCAM Post-Processor coordinates P0 (THC Lock) and P1 (Torch Relay) directly in the generated G-code stream:

  • 1. Cut Start: Emits M3 (which runs m3.py to probe, fire via M62 P1 + wiggle, and dwell), or when useM3M5 is disabled, emits M62 P1 directly before the lead-in motion block.
  • 2. THC Lock/Unlock (P0): Emits M63 P0 before HSS tube corners, small holes, or lead-outs to lock the hardware THC in sync with motion, and M62 P0 once steady cutting speed is reached.
  • 3. On-The-Fly Arc Stop (P1 — Zero-Overburn Early Torch-Out): Immediately before the lead-out or overburn G1/G2/G3 block, the RotaryCAM Post-Processor emits M63 P0 (lock THC so voltage decay cannot cause torch diving) and M63 P1 (kill torch relay on the very first interpolation step of the lead-out/overburn move), followed by M5 after the move completes.

M62 P0                          ( Unlock Hardware THC at steady surface speed )
G1 X48.320 Y0.000 Z13.500 A264.200 F2200.0

( --- ZERO-OVERBURN EARLY TORCH-OUT ON LEAD-OUT / OVERBURN --- )
M63 P0                          ( 1. Lock Hardware THC before arc voltage decays )
M63 P1                          ( 2. Arm Torch Relay OFF on first step of overburn move )
G1 X48.350 Y0.000 Z13.500 A267.500 F2200.0   ( Torch extinguishes in motion across seam )
M5                              ( 3. Fast no-wiggle cleanup & immediate Safe Z retract )
Part II • Parameter Handshake (#1113 / #1110 / Z#3)

How 3D Ramp Lead-Ins Work in m3.py & RotaryCAM Post-Processor

Replace stationary vertical puddle plunges with a coordinated 3D diagonal or helical descent from Pierce_height (#2) down to Cut_height (#3) along the lead-in trajectory.

Overview: How 3D Ramp Lead-Ins Work in m3.py

In SimCNC's stock m3.py:190-205, the entire pierce cycle is strictly vertical and stationary: the torch fires at Pierce_height (#2), waits 100% of Pierce_delay (#4), and plunges straight down into the molten puddle to Cut_height (#3) before lateral motion begins.

To perform a 3D Ramp Lead-In—where the torch pierces at Pierce_height and then descends diagonally in X + Y + Z (+ A) down to Cut_height along the lead-in line or helical arc to deflect molten spatter away from the nozzle and shield—m3.py uses a three-parameter handshake with the G-code program emitted by the RotaryCAM Post-Processor:

  • #1113 (Ramp_lead_in_pn): One-shot handshake flag set by G-code before M3 (1.0 = arm 3D ramp; 0.0 = standard vertical plunge).
  • #1110 (Material_thickness_pn): Tube wall / plate thickness used by m3.py to choose between a thin-sheet flying dwell (60%) and a thick-wall full-blowout dwell (100%).
  • #2 (Pierce_height) & #3 (Cut_height): Program Z coordinates referenced as Z#3 on the G-code lead-in move.
Step 07 • Ramp 1

Define Handshake Parameters & Material Thickness Fallback in m3.py

In m3.py:145-183, define the machine parameter numbers and a helper extract_thickness() to parse thickness from the SimCNC GUI cut chart string (in case #1110 is not emitted by G-code or a thicker material preset is selected in the UI):

m3.py (Lines 145–183) — Handshake Parameter Numbers PYTHON 
Ramp_lead_in_pn = 1113        # Set to 1.0 by RotaryCAM Post-Processor when 3D ramp lead-in is active
Material_thickness_pn = 1110  # Material thickness emitted by RotaryCAM Post-Processor

extract_thickness(text, unit) converts sheet-metal gauge numbers (26 ga–7 ga), metric strings (mm), fractions (3/8), or decimal inches into current machine units (inch or mm).

Step 08 • Ramp 2

Anchor Program Z to Pierce_height (#2) After Probing

When m3.py:439-443 finishes probing the tube/plate surface (touch_z) and lifts to physical pierce height, it sets the Program Z coordinate to Pierce_height:

m3.py (Lines 439–443) — Anchoring Program Z to Pierce_height (#2) PYTHON 
Pierce_height_position[Axis.Z.value] = touch_z + Pierce_height
d.moveToPosition(CoordMode.Machine, Pierce_height_position, Lifting_velocity)
d.setAxisProgPosition(Axis.Z, Pierce_height)
🔬 Why Anchoring Program Z to Pierce_height (#2) Is Required

Setting Program Z to Pierce_height (#2) establishes the metal surface as Program Z = 0.0. When m3.py exits with the torch still at Pierce_height, the very next G-code block can command Z#3 (Cut_height) in Program coordinates, and SimCNC will interpolate the exact Pierce_height → Cut_height Z delta simultaneously with X, Y, and A.

m3.py (Lines 544–573) — Reading #1113 & #1110 PYTHON 
try:
    ramp_lead_in_enabled = (float(d.getMachineParam(Ramp_lead_in_pn)) == 1.0)

    Material_thickness = float(d.getMachineParam(Material_thickness_pn))

Step 10 • Ramp 4

Implement Two-Tier Pierce Dwell (Flying Thin-Sheet vs. Full-Blowout Plate)

In the pierce delay section (m3.py:576-602), branch the stationary dwell time based on ramp_lead_in_enabled and Material_thickness:

m3.py (Lines 576–602) — Two-Tier Pierce Dwell Logic PYTHON 
if (Pierce_delay > 0):
    thresh_thin = 0.080 if unit == "inch" else 2.0
    if ramp_lead_in_enabled and Material_thickness <= thresh_thin and Pierce_delay < 400.0:
        # Thin sheet (<= 14 GA / ~0.080" / 2.0mm and short delay < 400ms):
        # Flying ramp lead-in: reduce stationary dwell to 60% (min 100ms)
        ramp_dwell = max(100, int(Pierce_delay * 0.60))
        max_time = time.time() + (ramp_dwell / 1000.0)
        while max_time > time.time():
            if not check_arc_ok(d):
                emergency("Torch went out while piercing")
            time.sleep(0.005)
    else:
        # Plate (> 14 GA / > 0.080" or Pierce delay >= 400ms) or standard stationary pierce:
        # Full 100% nominal dwell at Pierce_height for complete puddle blowout
        max_time = time.time() + (Pierce_delay / 1000.0)
        while max_time > time.time():
            if not check_arc_ok(d):
                emergency("Torch went out while piercing")
            time.sleep(0.005)
  • Tier 1 (Thin Wall / Sheet <= 0.080" / 2.0 mm & < 400 ms delay): Penetrates almost instantaneously; cutting the stationary dwell to 60% (minimum 100 ms) launches the diagonal XY+Z ramp on-the-fly while finishing blow-through.
  • Tier 2 (Heavy Wall / Plate > 0.080" / 2.0 mm or >= 400 ms delay): Dwells for the full 100% Pierce_delay at Pierce_height so the puddle blows completely through the bottom of the wall first, then uses the 3D ramp to descend to Cut_height during lateral lead-in motion rather than plunging straight down into rising slag.
Step 11 • Ramp 5

Skip Stationary Z Plunge & Reset #1113 at the End of m3.py

In the Move Cut Height section (m3.py:604-616), replace the unconditional descent from stock m3.py:200-205 with the conditional handoff:

m3.py (Lines 604–616) — Conditional 3D Ramp Handoff & Flag Reset PYTHON 
if ramp_lead_in_enabled:
    print("  >  3D Ramp Lead-In armed: Z remains at Pierce height for motion-synchronized ramp plunge")
    d.setMachineParam(Ramp_lead_in_pn, 0.0)  # Reset handoff flag
else:
    if (Pierce_height != Cut_height):
        print("  >  Move Cut height")
        Cut_height_position = d.getPosition(CoordMode.Program)
        Cut_height_position[Axis.Z.value] = Cut_height
        d.moveToPosition(CoordMode.Program, Cut_height_position, Descent_velocity)

✓ Why #1113 Is Reset to 0.0 Inside m3.py

Resetting Ramp_lead_in_pn (#1113 = 0.0) immediately consumes the flag as a one-shot token. If the next M3 is triggered from MDI or a G-code operation that does not set #1113=1, m3.py safely falls back to the standard vertical plunge to Cut_height.

Step 12 • Ramp 6

Emit the Coordinated 3D Ramp Sequence in G-Code (RotaryCAM Post-Processor)

To drive the m3.py 3D ramp logic from G-code, the RotaryCAM Post-Processor emits the coordinated ramp handshake automatically when 3D Ramp Lead-In (Flying Pierce) is enabled:

  • 1. Validate Minimum Lead-In Length: Before emitting M03, the RotaryCAM Post-Processor verifies that the lead-in line or arc length is at least minRampLeadLength (0.14" / 3.5 mm). If the lead-in is shorter than 0.14" (3.5 mm), it emits #1113=0 so m3.py plunges vertically first rather than attempting an overly steep ramp.
  • 2. Arm m3.py & Lock Hardware THC:
    RotaryCAM Post-Processor — Arming #1113 & #1110 Before M03 G-CODE 
    #1113=1         ( Arm 3D ramp handoff in m3.py )
#1110=0.25      ( Pass material / wall thickness to m3.py )
M03             ( Probes, lifts to Pierce Height #2, fires, dwells, leaves Z at #2 )
M63 P0          ( Keep hardware THC locked during 3D ramp so high arc V at #2 cannot dive Z )
  • 3. Execute 3D Linear or Helical Lead-In to Z#3:
    RotaryCAM Post-Processor — 3D Linear & Helical Arc Ramp Moves to Z#3 G-CODE 
    ( Option A: 3D Linear Ramp Lead-In )
G01 X1.2500 Y0.8000 Z#3 F120.0

( Option B: 3D Helical Arc Ramp Lead-In )
G17 G03 X1.2500 Y0.8000 Z#3 I0.0000 J0.1500 F120.0

( Unlock Hardware THC once torch reaches Cut_height #3 on the cut contour )
M62 P0

Because m3.py left the torch at Program Z = #2 (Pierce_height), SimCNC interpolates X, Y, Z (and rotary A on 4-axis tube lead-ins) simultaneously along the lead-in path and reaches Z = #3 (Cut_height) at the exact point where the lead-in meets the cut contour, where M62 P0 then unlocks the hardware THC.
