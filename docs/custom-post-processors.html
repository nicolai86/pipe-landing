Write Your Own Controller Post in Sandboxed Lua 5.4

Need a custom M-code for an older plasma table, a shop-built floating head, or a specific IHS probe cycle? Write a single .lua post-processor and run it on both 2D Flat Sheet and 4-Axis Rotary Tube/Structural jobs with Pack Mode parity built in.

Your custom post runs on the exact same api_version = 1 Lua 5.4 contract that powers RotaryCAM’s built-in controllers. If you have ever edited a SheetCam .scpost file, the hook layout will feel familiar right away.

  • Built for both 2D plate and 4-axis rotary: One post handles flat sheet, round pipe, HSS, open beams, and multi-stick Pack Mode without maintaining separate files.
  • Strictly sandboxed: No filesystem (io), no OS shell (os), and no external modules (package). Each run is capped at 4 MB of memory and 2,000,000 VM instructions, so accidental infinite loops abort cleanly in milliseconds.
  • Included in every paid tier: Custom Lua post-processors are unlocked on both Maker ($199) and Pro Shop ($399) licenses.

Step 01

Anatomy of a .lua Post-Processor (api_version = 1)

Every custom post starts with a global post metadata table. It tells RotaryCAM your post’s unique ID, output file extension, comment syntax, rotary feed mode, and Z-axis model.

Required Metadata Table Lua 5.4 
post = {
  api_version      = 1,
  id               = "shop_custom_thc",
  name             = "Shop Custom Plasma + THC",
  description      = "G38.2 touch-off with ref-distance skip and M62/M63 THC sync",
  file_extension   = "nc",
  comment_style    = "parens",   -- "parens", "semicolon", or "brackets"
  rotary_feed_mode = "g93",      -- "g93", "g94", or "spoofed_g94"
  z_model          = "explicit", -- "explicit" or "controller_managed"
}
Field Example Values What It Controls on Your Table
api_version 1 Required contract version. Always set to 1.
id "shop_custom_thc" Unique slug used in machine profiles (post_processor_id) and HTTP API URLs. Use lowercase letters, numbers, and underscores.
name "Shop Custom Plasma" Human-readable label shown in the Controller / Post-Processor dropdown.
description Short summary text Shown in the Post Processors list so operators know which table this post targets.
file_extension "nc", "tap", "ngc" File extension used when you download single-part or Pack Mode G-code.
comment_style "parens", "semicolon", "brackets" Sets comment framing ((text), ; text, or [text]) and configures the pre-save comment linter.
rotary_feed_mode "g93", "g94", "spoofed_g94" Chooses inverse-time (G93), standard units/min (G94), or 4D Euclidean feedrate spoofing for rotary cuts.
z_model "explicit", "controller_managed" "explicit" emits full CAM Z heights (required for 3D ramps and 4D HSS). "controller_managed" lets a controller macro own Z on flat plate.
Step 02

Lifecycle Hooks, ctx Fields & rc Helpers

Every hook function is optional. Omit any hook you do not need, and RotaryCAM falls back to clean RS-274 defaults so you only write the lines that differ on your controller.

1. Lifecycle Hooks

Hook Signature When It Runs & Return Contract
on_validate(ctx) Runs before generation. Return an error string (or { error = "..." }) to reject unsupported stock profiles or machine settings cleanly.
on_capabilities(ctx) Returns a table of per-job capability overrides (for example switching z_model or rotary_feed_mode between flat sheet and 4-axis tube).
on_preamble(ctx)
on_preamble_post_sim(ctx)		 Emits program header lines (units G20/G21, G90, G94, safe retract, material macros). on_preamble_post_sim runs right after simulator setup lines.
on_piece_start(ctx)
on_between_pieces(ctx)		 Pack Mode parity hooks. Emit per-stick/per-sheet headers, reset touch-off state, or insert bar-advance/operator pauses between nested pieces.
on_pre_cut_setup(ctx) Runs once per contour after the rapid move to the pierce XY/XA point and before on_pierce(ctx). Good for per-hole speed or material register updates.
on_pierce(ctx) Emits IHS probe, switch-offset G92 Z, pierce height, torch fire (M3), pierce dwell, and plunge (skipped when ctx.is_ramped is true). Return { thc_locked = true } or { thc_locked = false }.
on_torch_off(ctx) Extinguishes the arc (M5), restores G94 if needed, and retracts to ctx.safe_z. Return { thc_locked = true/false } so THC state tracking stays exact.
on_thc_lock(ctx)
on_thc_unlock(ctx)
on_inline_thc_suffix(ctx)		 Emits standalone THC lock/unlock lines (check ctx.reason for corners, small holes, or kerf voids) or appends an inline motion-sync word to a cut line.
on_hardware_kerf(ctx) Optional controller-side kerf compensation. Return a token list such as {"G41.1", "D1.500"} or {"G41", "P0.750"}.
on_dwell(ctx)
on_resolve_cut_z(ctx)		 Formats controller-specific dwells (such as G04 P vs G04 X) and optionally overrides the emitted cut Z height for a stroke.
on_center_spot(ctx) Emits center-punch or plasma dimple cycles for drill marks on flat plate or rotary tubes.
on_pneumatic_scribe_on(ctx)
on_pneumatic_scribe_off(ctx)
on_coaxial_scribe_touch_off(ctx)		 Controls pneumatic air-scribe solenoids or coaxial spring-loaded scribe touch-off cycles without firing the plasma torch.
on_rotary_unwind(ctx) Resets multi-turn rotary axis wrap safely (for example G92 A<rotary_mod_deg>) instead of unwinding a clamped stick backward.
on_footer(ctx) Restores G94, retracts to safe clearance, parks if desired, and ends cleanly with M30 or M2.

2. Built-In Helper Functions (ctx & rc)

Helper Call Purpose
ctx.emit(line) Appends one G-code line to the output stream.
ctx.emit_lines(tbl) Appends an ordered Lua array of G-code strings in one call.
ctx.set_state(key, val) Stores per-job state (read back from ctx.state[key] on later hooks), such as probe distance counters or active modal flags.
rc.fmt(v, dec) Formats number v to fixed decimal places dec with deterministic decimal dots (never scientific notation or locale commas).
rc.clamp(v, lo, hi) Clamps v inside [lo, hi] so dwells, feeds, or voltages never exceed controller bounds.
rc.round(v) Rounds v to the nearest integer (useful for millisecond dwells or integer register values).

3. Key ctx Fields Passed to Hooks

Category Available ctx Fields
Units & Heights unit_code ("G21" / "G20"), safe_z, pierce_z, cut_z, pierce_surface_z, probe_target_z, probe_feed, switch_offset
Cut Chart & Torch pierce_dwell_sec, plunge_feed, cut_feed, arc_volts, amps, kerf_width, thickness
Mode Flags is_flat, is_rotary, is_dynamic_z, is_rotary_g93, is_small_hole, is_ramped, is_pack_mode
Rotary & Context rotary_axis ("A", "B", "W"), rotary_mod_deg, reason (THC/unwind reason tag), settings (machine & custom post settings table)
Step 03

Worked Shop-Floor Example (~60 Lines)

Copy this complete custom post as a starting point. It skips redundant flat-sheet IHS touch-offs within ref_distance using a stateful cut_travel_since_probe counter, syncs THC lock/unlock on M63 P0 / M62 P0, supports 3D ramp lead-ins, and resets rotary wrap cleanly with modulo-360° G92.

shop_custom_thc.lua Lua 5.4 • Copy-Paste Ready 
post = {
  api_version      = 1,
  id               = "shop_custom_thc",
  name             = "Shop Custom Plasma + Sync THC",
  description      = "G38.2 touch-off with ref-distance skip, M62/M63 THC, and G93 rotary",
  file_extension   = "nc",
  comment_style    = "parens",
  rotary_feed_mode = "g93",
  z_model          = "explicit",
}

function on_preamble(ctx)
  ctx.set_state("has_probed", false)
  ctx.set_state("cut_travel_since_probe", 0)
  ctx.emit_lines({
    ctx.unit_code .. " G90 G40 G94",
    "(STOCK " .. rc.fmt(ctx.thickness, 2) .. " KERF " .. rc.fmt(ctx.kerf_width, 2) .. ")",
    "M63 P0 (THC LOCKED)",
    "G0 Z" .. rc.fmt(ctx.safe_z, 3),
  })
end

function on_piece_start(ctx)
  ctx.set_state("has_probed", false)
  ctx.set_state("cut_travel_since_probe", 0)
end

function on_pierce(ctx)
  local st = ctx.state or {}
  local ref_distance = (ctx.settings and ctx.settings.ref_distance) or 250
  local need_probe = (not st.has_probed) or ctx.is_rotary
    or ((st.cut_travel_since_probe or 0) >= ref_distance)

  if ctx.is_rotary_g93 then ctx.emit("G94") end
  if need_probe then
    ctx.emit_lines({
      "G38.2 Z" .. rc.fmt(ctx.probe_target_z, 3) .. " F" .. rc.fmt(ctx.probe_feed, 1),
      "G92 Z" .. rc.fmt(ctx.pierce_surface_z - ctx.switch_offset, 3),
    })
    ctx.set_state("has_probed", true)
    ctx.set_state("cut_travel_since_probe", 0)
  end

  ctx.emit("G0 Z" .. rc.fmt(ctx.pierce_z, 3))
  ctx.emit("M3 (" .. rc.round(ctx.amps) .. "A " .. rc.round(ctx.arc_volts) .. "V)")
  if ctx.pierce_dwell_sec > 0 then
    ctx.emit("G4 P" .. rc.fmt(rc.clamp(ctx.pierce_dwell_sec, 0.05, 10.0), 3))
  end
  if not ctx.is_ramped then
    ctx.emit("G1 Z" .. rc.fmt(ctx.cut_z, 3) .. " F" .. rc.fmt(ctx.plunge_feed, 1))
  end
  return { thc_locked = true }
end

function on_thc_lock(ctx)   ctx.emit("M63 P0 (THC LOCK " .. (ctx.reason or "CUT") .. ")") end
function on_thc_unlock(ctx) if not (ctx.is_dynamic_z or ctx.is_small_hole) then ctx.emit("M62 P0") end end

function on_torch_off(ctx)
  local st = ctx.state or {}
  local cut_step = (ctx.settings and ctx.settings.last_cut_length) or 100
  ctx.set_state("cut_travel_since_probe", (st.cut_travel_since_probe or 0) + cut_step)
  ctx.emit_lines({ "M63 P0", "M5" })
  if ctx.is_rotary_g93 then ctx.emit("G94") end
  ctx.emit("G0 Z" .. rc.fmt(ctx.safe_z, 3))
  return { thc_locked = true }
end

function on_rotary_unwind(ctx)
  ctx.emit("G92 " .. (ctx.rotary_axis or "A") .. rc.fmt(ctx.rotary_mod_deg, 3))
end

function on_footer(ctx)
  ctx.emit_lines({ "M63 P0", "G94", "G0 Z" .. rc.fmt(ctx.safe_z, 3), "M30" })
end
✓ Why Three Details in This Post Protect Your Torch

First, on_pierce always probes on rotary stock (ctx.is_rotary) because tube ovality and sag shift the top surface around the stick, while flat sheet skips extra probes inside ref_distance. Second, on_thc_unlock keeps THC locked on ctx.is_dynamic_z (4D square HSS) and ctx.is_small_hole so voltage spikes never dive the torch. Third, on_torch_off restores G94 before retracting to ctx.safe_z.

Step 04

Method A: Author, Validate & Assign Inside the Machines UI

The fastest way to build a custom post is directly inside RotaryCAM’s Machines dialog. Start from the closest built-in controller so you never have to guess probing or rotary framing from scratch:

  • 1. Open the Lua editor tab: Click ⚙ Machines in the top bar, then select the Post Processors (Lua) tab.
  • 2. Start from a template: Click Clone Built-In to copy an existing controller post (such as Mach4, LinuxCNC, or Generic RS-274), or click New Blank Post to start clean.
  • 3. Edit your hooks: Set a unique id and name in the post table, then update your probe, torch, THC, or unwind hooks.
  • 4. Run Validate & Preview: Click Validate & Preview. RotaryCAM compiles your Lua post against three real test jobs (Flat Sheet, 4-Axis Rotary, and Pack Mode) and runs GCodeGrammarLinter on all three outputs with instant pass/fail diagnostics.
  • 5. Save and assign to a table: Click Save Custom Post, then switch to your machine profile’s Controller & Compensation tab and choose your new post from the Controller / Post-Processor dropdown.
Step 05

Method B: Edit in VS Code & Automate via Local HTTP API

Prefer editing .lua files in VS Code, storing shop posts in Git, or running automated validation in CI? Talk straight to your running local RotaryCAM instance on http://localhost:3000 with four REST calls.

1. List All Posts & Download a Built-In Post to Edit

GET /api/post-processors Shell / curl 
# List every built-in and custom Lua post-processor
curl -s http://localhost:3000/api/post-processors | jq .

# Download a built-in .lua post as a starting point (example: mach4_ess)
curl -s "http://localhost:3000/api/post-processors/mach4_ess?download=1" -o my_custom_post.lua

2. Validate Before Saving (Syntax + Sandbox + Grammar Linter)

POST /api/post-processors/validate Shell / curl 
# Validate local .lua file across Flat, 4-Axis Rotary, and Pack Mode in mm (or "in")
jq -Rs '{ source: ., units: "mm" }' my_custom_post.lua \
  | curl -s -X POST http://localhost:3000/api/post-processors/validate \
      -H "Content-Type: application/json" \
      -d @- | jq .

3. Create, Update & Assign to a Machine Profile

POST / PUT /api/post-processors & PUT /machines/<id> Shell / curl 
# Create a brand-new custom post
jq -Rs '{ source: . }' my_custom_post.lua \
  | curl -s -X POST http://localhost:3000/api/post-processors \
      -H "Content-Type: application/json" \
      -d @- | jq .

# Push subsequent edits to an existing custom post ID
jq -Rs '{ source: . }' my_custom_post.lua \
  | curl -s -X PUT http://localhost:3000/api/post-processors/my_custom_post \
      -H "Content-Type: application/json" \
      -d @- | jq .

# Assign the custom post to a machine profile
curl -s -X PUT http://localhost:3000/machines/my_table_id \
  -H "Content-Type: application/json" \
  -d '{ "post_processor_id": "my_custom_post" }' | jq .

4. Delete a Custom Post

DELETE /api/post-processors/<id> Shell / curl 
# Remove a custom post (built-in posts are read-only and cannot be deleted)
curl -s -X DELETE http://localhost:3000/api/post-processors/my_custom_post | jq .
Step 06

Pre-Save Safety Checks & Troubleshooting (GCodeGrammarLinter)

Before you save a custom post or send G-code to your plasma table, RotaryCAM runs the same GCodeGrammarLinter used on all built-in controllers. Every check below catches real table hazards automatically:

Automated Safety Check Table Hazard Prevented How to Fix in Your Lua Post
Torch left on at EOF Dragging a live plasma arc across the table or into the chuck at job end. Emit M5 (or your controller’s torch-off M-code) in on_torch_off(ctx) and verify every pierce closes cleanly.
G0 rapid with live torch Blasting a molten slash across finished parts during traverse moves. Never emit G0 between torch fire and torch off. Move to pierce height before M3, and retract after M5.
G93 left active at EOF Next jog or MDI move runs at runaway inverse-time speed. Emit G94 in on_torch_off(ctx) (when ctx.is_rotary_g93 is true) and again in on_footer(ctx) before M30.
Missing M30 / M2 Controller hangs at end of file or refuses to rewind for the next stick. Always finish on_footer(ctx) with M30 (or M2 if your control expects it).
NaN or infinite coordinates Controller parser fault or unpredictable axis jump. Guard divisions against zero (e.g. feedrate or distance) and format every number through rc.fmt(v, dec) and rc.clamp(v, lo, hi).
Comment delimiter violation Syntax error on strict controls (nested parens on GRBL/Mach, parens on Acorn, or unbracketed text on WinCNC). Match post.comment_style ("parens", "semicolon", or "brackets") and avoid nested ( ) or stray ; inside comments.
Sandbox memory / op timeout Runaway script freezing CAM generation (4 MB RAM or 2,000,000 VM ops exceeded). Check while / for loop exit conditions and avoid building massive strings inside per-segment hooks.
⚠ Always Dry-Run New Custom Posts With Torch Disabled

Even after GCodeGrammarLinter passes, run your first cut on a new custom post in Dry-Run (plasma power off) with one hand near E-Stop. Confirm IHS probe direction, switch offset, safe Z clearance over rotary corners, and M62/M63 THC LED timing before striking your first real arc.
